# 实验协议

预训练通过两种语言交替 microbatch，在每个完整 optimizer update 内严格处理相同 Token 数。后训练保留完整样本，按有效监督 `loss_tokens` 补足落后语言，使中英 Token 数近似均衡；记录两种语言的输入 Token、监督 Token 和实际偏差，不能将样本条数各半当作 Token 各半。汇总指标同时报告 pooled 和中英各 50% 的 `macro_languages`，后者作为均衡主结果。

## 实验前先写问题

每个实验明确问题、唯一主要变量、保持固定的条件、训练预算、模型选择指标、停止条件和预期证据。一次同时改变模型大小、Tokenizer、数据和 Batch，结果就不能简单归因于其中某一项。

预训练优先回答：学习率改变收敛速度与稳定性吗？在相同有效 Token 预算下，更大 Batch 是否改变验证 Loss？更长上下文是否增加峰值显存和每步时间，是否改善相同评测窗口中的预测？

后训练优先回答：相同 Base 与数据下，全参数 SFT 和 LoRA 的任务表现、可训练参数、显存和成本如何变化？DPO 是否改变固定任务上的格式与正确性？首版 DPO 前后对比不能证明 DPO 优于继续 SFT。

## 数据隔离

先确定文档或原始问题的组，再划分训练/验证/测试，最后编码、增强、截断、打包和构造偏好。重复文档与同源中英样本尽量归入同一组。固定快照和哈希，准备结果写入 manifest。不能把长文档切成相邻 Token 段后随机分区。

Tokenizer 仅使用预训练训练分区。验证集用于超参数和 Checkpoint 选择；测试集由明确的最终评测操作打开。公开任务有可能已经存在于 Base 预训练语料中，即使本项目划分正确，也无法据此证明没有预训练污染。

## 预算与公平性

全参数 SFT 与 LoRA 固定 Base revision、数据、模板、Loss Mask、最大长度和有效 Token 预算，分别调学习率并使用相同调参预算。记录截断样本比例和 response Token 数，不能只比较 epoch 名称。

预训练全局 Batch 的有效 Token 数近似为：

\[
B_{\mathrm{tokens}} = B_{\mathrm{micro}} \times T \times G
\]

其中 `G` 是梯度累积次数。存在 padding 或可变长度时，以真正参与 Loss 的 Token 数为准。比较上下文成本时同时报告 `tokens/s`、每步时间、峰值显存、数据准备开销与最终验证指标。

成本预测必须由实际训练测速更新：

\[
t_{\mathrm{train}} \approx N_{\mathrm{tokens}} / v_{\mathrm{tokens/s}},\quad
C = p_{\mathrm{GPU/h}}\, t_{\mathrm{instance/h}} + C_{\mathrm{storage}} + C_{\mathrm{transfer}}
\]

测速包括预热后持续训练的有效步；小矩阵环境探针不等于训练吞吐。为下载、验证、保存和平台结算留出余量。训练预算守卫只估计当前进程的计算部分；不能观察云实例全部存活时间、其他进程、持久存储和网络账单。

训练预算在 optimizer update 边界检查，可能增加一次 update 及后续验证/保存开销；不要把退出阈值写成云账单精确上限。默认预留 100 元用于数据、存储、重跑等，其是否足够仍需实测。

## 已实现的预训练对照计划

```bash
python -m llm_lab.experiments --config configs/experiments/pretrain_ablation.json
```

默认只生成 `runs/pretrain_ablation/plan.json` 和各组配置，不执行训练。五组分别是基线、学习率调整、有效 Batch 翻倍、上下文 512、上下文 2048。每组使用相同的 262144 个有效训练 Token，调整累积以控制上下文组的每次更新 Token 数。

262144 Token 是机制与成本检查用的小规模计划，不能据此形成充分预训练或最终收敛质量的结论。只有远程测速与价格确定、数据已准备后，再显式执行：

```bash
python -m llm_lab.experiments --config configs/experiments/pretrain_ablation.json --hourly-rate-cny 2.0 --execute
```

小时价为语法示例，须替换实际值。某组因预算提前停止时，后续组不会继续；应报告实际 Token 数，并避免把不等训练量的结果称为严格等量对比。

## 指标定义与边界

语言建模 Loss 是有效目标 Token 上的平均负对数似然。`PPL = exp(Loss)`；当 Loss 很大时需要处理指数溢出。不能直接比较不同 Tokenizer 下的 PPL，同一实验内也应保持相同语料和预处理。

意图准确率按意图完全一致计分；JSON 有效率需要可解析并满足约定字段；完整成功要求格式、意图和所有槽位符合任务标注。槽位 F1 使用明确定义的槽位/值匹配，不混用 Token 级 BIO F1 和精确值集合 F1。最终以评测代码的实际定义为准，并写入报告。

DPO 的训练 Loss 或偏好准确率下降/上升不能替代独立任务评测。人为构造的错误可能比真实模型错误简单，模型可能只学会识别构造模板；报告应保留这种限制。开放聊天只用固定样例展示，不据少量样例宣称通用中英能力。

## Checkpoint 与结果选择

每次运行保存配置快照和来源记录，定期保存 `last`；使用验证指标选择 `best`。训练中断后从 `last` 恢复时继续计数，不能重新开始 warmup 或偷偷重置数据位置。若修改数据、架构、Optimizer 或关键采样设置，应创建新运行并解释迁移。

恢复正确性验收使用小模型：相同初始化，一路连续执行 N 步，另一路执行 K 步后保存并恢复至 N 步，对比参数、优化器、学习率、步数和数据进度。FP32 可用更严格容差；BF16 容差必须在远程相同环境验证。非确定性算子可能需要环境约束，不能把近似一致写成逐位一致。
