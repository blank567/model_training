## 研究问题与主比较

LoRA是一种SFT参数更新方式。主比较为同一个303,350,784参数预训练Base分别进行全参数SFT和LoRA-SFT，固定同一100,000条训练数据、32K分词器、聊天模板、回答/EOS监督、种子、样本顺序与有效Batch。

- 初始化沿用`runs/pretrain_300m_3b_20261025_150858/best.pt`，SHA256为`69b24779315561390bddbef18ce5ce9b505052a3ca697a0a651dfa6ea3c2bf45`。
- 数据沿用`artifacts/posttrain/sft_expansion_20261027_215627/sft_100k/manifest.json`，data_identity为`ad2e58f22c741c22ed029e2b53d67d5722b93e0c9dcbb88617598abcb4a6a3e3`。
- 全参数对照为当前100k实验；LoRA主比较独立从同一Base开始。另在已SFT权重上加LoRA属于后续适配课题，不能混入这个方法比较。
- 比较任务表现、原语料保持、峰值显存、真实吞吐、GPU时长、训练参数与Checkpoint体积。LoRA不保证更准确、更快或不遗忘。
- 当前全参数配置经历过不同阶段的调参；要报告两种方法各自尝试的配置数和GPU时长，不声称具有严格相等的历史搜索预算。

## 第一组工作配置

以下是初始候选，尚未证明最优。

| 参数 | 设计值 |
| --- | --- |
| LoRA rank / alpha | 16 / 32，采用标准alpha/r缩放 |
| LoRA dropout / bias | 0.0 / none；保留Base既有dropout |
| 目标 | 每层attn.q、attn.k、attn.v、attn.out、gate、up、down |
| 冻结 | 全部Base参数，包括Embedding、共享lm_head及RMSNorm |
| 学习率候选 | 5e-5、1e-4、2e-4；中心工作值1e-4 |
| Micro / 累积 / 有效Batch | 8 / 4 / 32 |
| 精度 / seed | BF16计算 / 42；不引入量化变量 |
| 数据 / 上下文硬上限 | 同一100k正式训练集 / 1,024 Token，按真实长度补齐 |
| 优化 | AdamW，betas=[0.9,0.95]，weight decay=0.01，梯度裁剪1.0 |
| 调度 / 最终训练量 | 对齐当前Full：3轮cosine，实际最多2轮；总调度9,375步、warmup282步，正式终点6,250步 |
| 初筛 | 同一冻结计划先运行至3,125步，即1轮；胜出配置从完整LoRA last恢复至6,250步 |
| 验证/保存/记录 | 对齐当前Full的100/100/10次更新；W&B、TensorBoard、JSONL同时记录 |

初筛暂停通过独立probe参数执行，不能把同一冻结配置中的epochs改成1再改回2；否则会改变调度或恢复身份。rank或目标层改变则必须创建新实验，从Base重新初始化，不能把旧Adapter当作新rank继续训练。

## 顺序实验，避免完整网格

| 阶段 | 改变变量 | 固定项 | 新增候选 |
| --- | --- | --- | ---: |
| A，先执行 | LR=5e-5/1e-4/2e-4 | r16、alpha32、全部7类线性层、同一1轮筛选预算 | 3 |
| B，按A结果决定 | r8/16/32，alpha=2r | 选定LR与覆盖范围，保持alpha/r=2 | 最多2，复用r16 |
| C，可选 | q/v与全部7类层 | 同rank、同LR、同训练预算 | 最多1 |
| D，主比较 | 胜出LoRA从1轮继续至2轮 | 原冻结计划、优化器、RNG与数据游标不变 | 1次继续训练 |

初筛只缩小候选，不证明1轮时的排名一定保持到2轮。若候选接近，应保留前两名进行更长验证，再决定是否扩展rank或注入范围。先完成阶段A，不一次提交所有可选实验。

阶段C固定rank但覆盖范围改变时，可训练参数量也会改变；须报告实际参数数目，不能称为等参数预算的纯位置对照。额外seed实验也应给Full与LoRA各自安排对应重复，不用单边多种子结果替代公平比较。

## 当前结构的参数量

已用本地meta设备实例化当前Decoder检查结构；没有在本机训练或使用GPU。24层、hidden1024、KV宽度256、FFN2816；全部7类目标共168个Linear。

对于一个Linear，LoRA新增参数为r×(in_features+out_features)。

| 覆盖范围 | r / alpha | 新增可训练参数 | 相对原Base参数量 |
| --- | --- | ---: | ---: |
| Attention+MLP全部7类 | 8 / 16 | 3,489,792 | 1.15% |
| Attention+MLP全部7类 | 16 / 32 | 6,979,584 | 2.30% |
| Attention+MLP全部7类 | 32 / 64 | 13,959,168 | 4.60% |
| 仅q/v | 16 / 32 | 1,277,952 | 0.42% |

比例分母是原303M Base；PEFT显示的trainable%若将Adapter也计入总参数，r16全部层约为2.25%。r16的FP32 Adapter张量约26.63MiB，不包含优化器和元数据。训练仍需要Base权重、激活及反向传播，不能按参数缩减比例直接推算显存和速度。

## 验证与最终测试

1. 训练内checkpoint继续使用同一主验证995条保存best，以便对齐当前Full。辅助验证2,000条用于新任务覆盖、候选选择和生成诊断；在开始前冻结候选排序与相近配置的取舍规则，单列原语料保持指标，不用临时组合总分挑结果。
2. 原主测试1,000条已经用于选配置，应视为历史开发参考。现有辅助测试1,000条会在当前Full完成时评测，后续不能称为从未查看的LoRA最终测试。
3. 在任何LoRA调参前，从未使用余量另冻结LoRA阶段最终测试1,000条：排除100k训练、所有已有验证/测试、内容抽审、已用于调参的题及其重复组。只生成文件及身份统计，不把题目送入调参反馈。该新测试目前尚未构建。
4. 最终选择LoRA配置和Checkpoint后，Full与LoRA对相同新测试1,000条全部计算回答Loss，也全部自由生成；不能把64条抽样生成写成1,000条生成评测。统一贪心或同一采样设置、生成预算、模板与EOS规则，不截断问题。
5. 对可机械判定的格式/字段任务报告有效率、约束通过率或精确匹配；对开放问答/摘要/改写单列引用重叠和盲审结果。Loss、EOS停止率和ROUGE均不等于任务正确率，不编造统一正确率。
6. 新增候选的分类与抽取供应有限，100k已消耗其中大量样本。冻结前核对余量任务分布，缺失任务用单独的可验证挑战集补充并单独报告，不误标问答凑配比。
7. 与当前Full相同的固定预训练验证窗口持续记录遗忘。预留测试只在配置锁定后评测；不要根据最终测试结果继续调LR/r/dropout再称其独立测试。

两轮是训练量对照终点，最终使用验证最佳Adapter而非默认使用最后一步。固定两轮与自动早停属于不同实验协议；若另做早停，事前冻结耐心值和最小改善阈值，并单列实际Token预算。冻结Base不保证函数行为不遗忘，必须实测。

## 工程接入与Checkpoint

- 新增独立`src/llm_lora/`和`scripts/train_lora.py`；复用已有数据读取、一次因果错位、回答Token归一化、采样和评测函数。不要向已冻结的`src/llm_sft/`或`src/llm_lab/`加入文件，也不修改`scripts/train_sft.py`，因为这些路径参与旧实验源码指纹。
- 项目锁定PEFT0.17.1；优先用低层Adapter注入接口适配普通nn.Module，明确列出实际目标层，不直接套Qwen的q_proj等名字或HF CausalLM训练器。
- 当前ModelConfig是dataclass，Decoder.forward需要属性式配置。PEFT0.17.1有读取config.to_dict()/dict.get()的路径；要在新接入层提供保留属性访问的配置视图或包装模型，并验证，不能把原模型config直接改成普通dict，也不修改原配置类去迁就库。
- 注入模型必须匹配预期168个Linear，默认B零初始化时eval输出与原Base在数值容差内相等；优化器只包含Adapter参数，非LoRA梯度为空，短测前后冻结Base张量保持一致。
- best仅保存Adapter、LoRA配置和Base/分词器/数据身份；last另保存Adapter优化器、调度器、随机数、Sampler游标和预算状态。不能只保存safetensors就宣称可以完整断点恢复。
- 新身份同时绑定原Base SHA、原训练源码指纹、新LoRA代码与PEFT版本。装载不匹配的Base、rank、目标层、模板或数据版本应拒绝。合并导出为可选产物，先验证合并前后输出一致，再保存副本，保留未合并Adapter。
- 复用GPU锁与预算账本。正式结果在runs根目录，名字标注data100k、lr、r、alpha、目标范围、micro/累积/有效Batch、调度/stop与时间戳；助手短测在runs/assistant/smoke或benchmarks。
- 先完成CPU数值/冻结/保存装载/恢复一致性检查，再等当前训练和评测结束后跑约32步受限GPU短测。实测显存与吞吐后再估时长和费用，不预先承诺比Full快几倍。
