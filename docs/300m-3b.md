## 显存与磁盘

现有实现以 FP32 创建参数，仅在 forward 使用 autocast；BF16 不会把参数、梯度和 AdamW 状态全部变成两字节。按参数、梯度与两份 AdamW 状态各 FP32 估算，静态张量约 **4,853,612,544 bytes（4.52 GiB）**。这不包括激活、Attention 临时张量、词表 logits/FP32 Cross Entropy、优化器临时张量和 CUDA 缓存，不能拿它当峰值显存。micro batch 4 与激活重算只是保守起点，48GB 单卡能否稳定运行、是否应改为 8×2，均须短测。

完整 Checkpoint 包含模型和两份 AdamW 状态，主要张量约 **3,640,209,408 bytes（3.39 GiB）/份**，另有少量元数据。现有保存逻辑同时保留 `last.pt` 与 `best.pt`，原子替换或复制期间还可能存在一份临时文件，仅这三份就约 **10.17 GiB**。训练前需在已有语料、100M 产物、缓存及日志之外，预留至少 **12 GiB 的新增可用空间**；若还要求额外保留 8 GiB 数据盘水位，则启动前可用空间至少应约 **20 GiB**。实际以当前磁盘及 Checkpoint 大小核对，不能沿用之前验收时的剩余空间数字。

本方案不自动清理旧数据、Checkpoint 或缓存，也不在当前 100M 运行期间竞争 GPU。

## 时间与费用边界

相对于 100,092,672 参数、1,000,013,824 个处理 Token 的 100M 方案，`参数量×处理量` 约增至 **9.092 倍**。这只是主要计算量比例：模型结构、硬件效率、激活重算、验证与大 Checkpoint 保存都会改变实际耗时，不能据此给出实测训练时间。正式时间与费用须用 300M 的稳定 Token/s 推算，并至少覆盖一次验证和保存周期。

旧 100M 配置的 60 元运行上限与每次启动 18 小时上限，不应直接作为 300M / 3B 能完成的承诺。候选暂记 180 元单次实验累计费用上限和每次启动 72 小时上限，付费单价仍留空；这两个上限是待复核的停止条件，不是已授权消耗额或总价估计。在参考单价 3.03 元/小时下，180 元最多覆盖约 59.4 小时训练进程时间，费用条件可能先于时间条件触发。

项目总额仍不超过 500 元，并保留 100 元余量；所有付费实验共享 `runs/budget_ledger.json`。账本累计的是训练进程估费，最终可用额度须结合平台实际账单扣除数据准备、空闲、磁盘等费用。若达不到测算所需预算，应先调整实验范围，不能仅把运行上限提高而宣称完成 3B。

## 正式启动前

1. 等当前 100M 运行完成，保存报告并核对实际账单、剩余磁盘和训练环境。
2. 新增约 2B 与旧约 1.1B 已合并验收，启动前核对上述已发布 manifest SHA256 及评测身份。简体规则、Tokenizer 身份及独立测试隔离沿用已验收的数据契约。
3. 仅做配置核验时执行 `python -m llm_lab.cli pretrain --config configs/pretrain/300m_3b.candidate.json --validate-only`，此命令不训练。
4. 在用户启动 GPU 前先冻结带时间戳配置，填写实际单价并复核停止上限；不要改写当前 100M 的运行文件。32 步中断检查保持正式 `max_steps=183106`，不能用 `--max-steps 32` 缩短学习率计划。
5. 短测验证无 OOM、Loss/梯度有限，并记录峰值显存与稳定吞吐；需要调整 Batch/重算等身份字段时，为调整后的候选新建实验，不能强行恢复先前配置。
6. 由用户自行启动正式训练，使用原冻结配置和 `last.pt` 严格恢复；最终独立测试只用于报告，不用于选择结构和超参数。

本次核验没有远程连接、GPU 训练或 300M 完整 CPU forward。参数量来自本地 meta 模型；显存、磁盘和成本为源码张量与保存逻辑的算术估计，均有明确范围。
