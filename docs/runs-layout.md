# runs 目录与实验归属

用户自行启动的实验结果保留在 `runs/` 根目录，继续沿用原来的训练、推理与恢复路径。助手代跑的历史记录按用途归入 `runs/assistant/`；仅移动已结束、确认没有代码、配置或已发布数据依赖的记录。路径调整会影响现有使用时，保留原位。

本次已归档21项独立助手记录（277个文件），505个保护文件的inode、大小、修改时间未变，训练代码指纹保持不变，没有删除文件。实际项目以 `runs/assistant/organization_manifest.json` 的旧路径、新路径及逐文件摘要为准：

```text
runs/
├── pretrain_100m_1b_20261024_192116/  # 用户的 100M 正式实验
├── pretrain_300m_3b_20261025_150858/  # 用户的 300M 正式实验
├── <用户手动实验、正式 SFT 输出>/
├── configs/                        # 原有冻结配置与环境文件
├── logs/                           # 原有控制台日志
├── plans/                          # 控制变量实验计划
├── assistant/
│   ├── benchmarks/                 # 训练吞吐、显存和分词测速
│   ├── inference/                  # 生成对比等推理记录
│   ├── data_prepare/               # 已结束的数据获取、制备与筛选记录
│   ├── system/                     # 环境探针、依赖快照、停止及清理报告
│   ├── smoke/                      # 预留给今后新建的助手短测
│   └── organization_manifest.json  # 本次整理的迁移映射
├── budget_ledger.json              # 共享费用估算账本
├── .gpu_training.lock              # 共享 GPU 锁
└── README.md                       # 运行目录索引
```

`runs/configs/` 中由助手准备、等待用户启动的正式 SFT 配置仍属于用户实验，保持原路径。正式输出继续在名称中标明模型、学习率、Batch、训练量等参数，完整参数以各实验的 `config.json` 为准。

## 保留原位的例外

以下助手历史产物也有现存引用，不为目录整齐而移动：

| 项目 | 保留原因 |
| --- | --- |
| `pretrain_100m/` | 保留历史日志与配置；2026-10-27用户明确同意后，其旧权重已删除，不再可恢复 |
| `pretrain_100m_probe20/` | 仍被配置引用 |
| 三个 `sft_data_prepare_*` 目录 | 已发布数据的构建配置记录了这些路径 |
| `sft_300m_full_20261026_190101/` | 旧状态查询仍引用该短测目录 |
| `pip-freeze.txt` | 环境安装脚本仍写入此路径 |
| `clear_300m*.json` | 既有状态记录仍引用这些文件 |

`wandb/` 等共享目录不按助手产物整体移动；环境脚本可能再次创建它们。账本和 GPU 锁保持原路径及文件身份，账本中的历史 `run_id` 也保留原值。

## 后续使用约定

新建、由助手代跑的独立短测或工具任务，优先直接指定 `runs/assistant/<用途>/` 下的输出路径。用户正式实验继续使用原启动器；不为整理目录修改已经冻结的训练实现、配置或 Checkpoint。

本次整理不删除实验内容，不建立旧路径符号链接，也不批量替换历史 JSON 中的路径。旧快照保持原样，通过迁移映射查找其当前位置；运行中的任务及其依赖不移动。配置、恢复和后台训练的具体命令见 [SFT 训练手册](sft-training.md)。

后续2026-10-27清理属于用户另行授权，删除了两组指定旧基线权重及测试/缓存/废弃数据载荷；不改变上述归档时的历史记录。具体范围和保留内容见 [空间清理报告](storage-cleanup-20261027.md)。
